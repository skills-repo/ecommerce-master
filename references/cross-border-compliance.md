# 跨境电商合规手册（Cross-border Compliance Playbook）

> 配套 [skills/cross-border-expansion](../skills/cross-border-expansion/SKILL.md)。本篇聚焦「落地前必须搞清楚的税务与海关合规」，
> 这是子技能正文装不下的决策增量：按国家给出注册阈值、申报路径与豁免规则。
> 本文为方向性指引，不构成法律/税务意见；大额业务须咨询持牌顾问。

## 1. 决策树：我的订单要不要注册 VAT / 销售税？

```
开始
 ├─ 发往欧盟 (EU-27)？
 │   ├─ 年跨境 B2C 营业额 ≥ €10,000（全 EU 合计）？
 │   │   ├─ 是 → 必须在收货国注册 VAT，或走 OSS 一站式申报
 │   │   └─ 否 → 可在本国（成立国）按本国 VAT 申报（MOSS/OSS 阈值内）
 │   └─ 货值 ≤ €150 且非 EU 境内发货？
 │       ├─ 是 → 走 IOSS（Import One-Stop-Shop）在清关时代收 VAT
 │       └─ 否 → 目的国 VAT + 可能进口关税
 ├─ 发往英国 (UK)？
 │   ├─ 年营业额 ≥ £85,000 → 注册 UK VAT
 │   └─ 货值 ≤ £135 → 由卖家在销售时代收 UK VAT（不走邮政代缴）
 ├─ 发往美国 (US)？
 │   ├─ 无联邦级销售税 → 看州
 │   └─ 在某州「经济关联 (economic nexus)」超阈值（各州 $100k 或 200 笔）
 │       → 在该州注册并代收销售税
 └─ 发往加拿大 / 澳洲 / 日本？
     ├─ CA：GST/HST（联邦）+ 省税；注册阈 CAD $30,000
     ├─ AU：GST 10%，注册阈 AUD $75,000
     └─ JP：消费税 10%，无小规模纳税人进口代缴豁免时需 JCT 注册
```

**关键判断**：先算「经济关联 / 营业额阈值」，再决定注册哪个辖区的税号。
阈值以下可不注册，但一旦跨越阈值，回溯期内的税单风险由卖家承担。

## 2. 选型矩阵：清关与 VAT 申报路径

| 场景 | 推荐路径 | 适用 | 注意 |
|------|----------|------|------|
| EU 小包 ≤€150 | IOSS | 直邮、低客单价 | 需在结账页明示含 VAT；平台/物流代传 IOSS 号 |
| EU 多国 B2C ≥€10k | OSS 统一申报 | 已规模化 | 仍需在各国算税率，但只向本国税局报一次 |
| 本地仓 / FBA | 目的国 VAT 注册 | 已囤货 | 库存所在国必须注册，不可走 OSS |
| UK ≤£135 | UK VAT 代收 | 直邮英国 | 由卖家代收，别让邮政代缴导致双重征税 |
| US 跨州 | 各州销售税注册 | 有 nexus | 用 TaxJar/Avalara 自动算率；市场Facade 代征时核对 |

## 3. 可运行命令 / 流程

### 3.1 用 Stripe Tax 自动算税（如已接入 payment-integration）
```bash
# 创建税务行为（示例：对发往德国订单代收 19% VAT）
curl https://api.stripe.com/v1/tax_settings \
  -u "$STRIPE_SECRET_KEY:" \
  -d "status=active"
# 在创建 PaymentIntent / Checkout Session 时携带 shipping_details
# Stripe Tax 会自动按收货地址匹配税率并生成税务报告
```

### 3.2 本地快速核对阈值（确定性脚本）
```python
# thresholds.py — 判断某市场是否触发注册义务（纯标准库）
THRESHOLDS = {
    "EU_OSS": 10000,   # EUR，全 EU 合计 B2C
    "UK": 85000,       # GBP
    "CA": 30000,       # CAD
    "AU": 75000,       # AUD
}
def needs_registration(market, annual_eur):
    t = THRESHOLDS.get(market)
    return t is not None and annual_eur >= t
print(needs_registration("UK", 90000))   # True
```

### 3.3 HS 编码与关税估算
- 在 [HS 编码查询] 或目的国海关数据库查 6–10 位编码。
- 估算公式：`到岸成本 = 货值 + 运费 + 保险`；`关税 = 到岸成本 × 关税率`；
  `进口 VAT = (到岸成本 + 关税) × VAT率`（IOSS/OSS 下由销售时代收，不二次缴）。

## 4. 落地成本建模示例（确定性）

假设：一件服装货值 $20，运费 $4，发往德国（VAT 19%），关税税率 12%，支付手续费 2.9%+$0.30。

```
到岸成本 (CIF)      = 货值 20 + 运费 4        = 24.00
进口关税            = 24.00 × 12%             = 2.88
应税基数 (含关税)   = 24.00 + 2.88            = 26.88
进口 VAT (IOSS)     = 26.88 × 19%             = 5.11
支付手续费          = (20+4+2.88+5.11)×2.9% + 0.30 = 0.94
────────────────────────────────────────────
买家到手总价        = 20+4+2.88+5.11+0.94     = 32.93
卖家毛利 (不含货本) = 售价 - 运费 - 关税 - VAT - 手续费
```

**解读**：VAT 通常向买家代收并全额上缴，不进毛利；真正吃掉利润的是关税 + 运费 + 手续费。
若想维持 30% 毛利，标价需反推：`标价 = (货本 + 运费) / (1 - 关税率 - 支付费率 - 目标毛利)`，
再叠加代收 VAT。把这套公式固化成 [skills/cross-border-expansion](../skills/cross-border-expansion/SKILL.md) 的落地成本表，
每次扩张新市场只换税率参数。

## 6. 典型坑与规避

1. **双重征税**：邮政渠道在清关时代收了 VAT，结账时又收一次 → 货值≤阈值的国家务必
   用 IOSS / 卖家代收，关掉邮政代缴。
2. **阈值回溯**：以为「今年没超就不注册」，结果 Q4 超了，税局要补全年 → 用滚动 12 个月
   监控，超 80% 阈值就提前注册。
3. **B2B 误用 OSS**：企业客户有有效 VAT 号时应走「逆向征收 (reverse charge)」，
   不通过 OSS 代收，否则对方无法抵扣。
4. **本地仓 VAT 漏注**：把库存发到 DE 仓却只注册了本国 VAT → 德国税局视同逃税，
   库存可能被冻结。
5. **数字商品特殊规则**：软件/电子书等数字服务按「消费者所在地」征税，规则与实物不同，
   别套用实物阈值。
6. **IOSS 不适用 ≥€150**：高客单价包裹必须目的国清关缴 VAT，IOSS 只覆盖 ≤€150。
7. **运费未计入应税基数**：德国等按 CIF（含运费/保险）计 VAT → 漏算运费会少缴被罚。
8. **豁免国误判**：阿联酋/沙特有 VAT 但无 OSS 机制 → 需单独注册，不能套 EU 流程。
9. **退货不退 VAT**：B2C 退货须同步退 VAT，否则买家投诉 + 税务不一致。
10. **货币换算时点错**：用下单日汇率还是清关日汇率 → 提前在成本表固定一种并留痕。
